## 结论与范围

项目已形成可运行的 MVP：网页浏览 → 视频检测 → 选择 Chromecast → 投屏遥控。当前不能称为“所有细节都完善”：已确认断开行为与文案不符、系统播放命令映射错误，以及视频当前状态与列表边界问题；电视端的完整验收记录仍不足。

本次按“全面检查并给出优化项”执行，没有修改产品源码或现有测试，没有安装到真实手机、连接电视或发送 Cast 命令。保留开始时已有的 13 个修改文件，新增本报告与独立复现材料。检查基于 `feat/improvement` 工作区的实际文件，包含未提交修改。

## 需要优先处理的问题

P1 表示优先处理的核心行为问题；P2 表示下一轮应修复的问题。等级表示本项目的修复次序，不代表已经发生事故。

| 编号 | 优先级 | 问题与影响 | 证据与建议 |
| --- | --- | --- | --- |
| F1 | P1 | “仅断开手机连接”不能保证电视继续播放。单发送端会停止电视，违背按钮和 README 表达的预期。 | `DevicePicker.swift:13` → `CastManager.swift:154` 调用 `endSessionAndStopCasting(false)`。锁定的 4.8.6 SDK 头文件和 [Google 官方 API 文档](https://developers.google.com/cast/docs/reference/ios/interface_g_c_k_session_manager) 均明确：只有一个发送端时忽略 false，仍停止播放。先修正文案与功能承诺；若必须保留电视播放，需要单独验证可行的会话策略，不能只把参数改为 false。未实际控制电视。 |
| F2 | P1 | 系统“播放”“暂停”被实现为切换状态。已经暂停时再收到暂停命令，会调用播放；已经播放时收到播放命令，则会暂停。 | `NowPlaying.swift:11` 和 `:14` 都调用 `togglePlayback()`；`CastManager.swift:182` 按当前状态选择相反动作。改为明确的 play/pause 操作，仅 toggle 命令使用切换。[Apple 的命令定义](https://developer.apple.com/documentation/mediaplayer/mpremotecommandcenter) 将三者分开。代码路径确认，未验证真实锁屏命令是否可达。 |
| F3 | P2 | A → B → A 切换播放时，返回 A 的当前状态上报可能被去重吞掉，列表仍将 B 当作当前视频。 | `sniff.js:39` 按每个 URL 的最后一次完整记录去重，但“当前视频”是跨 URL 的状态。运行实际脚本的 Node 事件夹具得到 `[A, B]`，预期 `[A, B, A]`。应将激活状态切换与媒体元数据去重分开，并补真实 WebKit 回归测试。 |
| F4 | P2 | 两个 frame 同播一个 URL 时，其中一个换片会错误清除另一个仍在使用的视频的当前标记。 | `VideoCandidate.swift:86` 直接将旧 URL 的 `isCurrent` 设为 false，没有检查其他 frame 的引用。实际 Swift 模型复现：frame one 仍播放 shared.mp4，模型却标 false。按活动 frame 集合推导当前状态，并考虑 frame 移除时的失效处理。 |
| F5 | P2 | 候选列表的 100 条上限不是硬上限。全部候选标为当前时，无法淘汰任何项。 | `VideoCandidate.swift:112` 仅淘汰非当前项。向实际模型写入 150 个不同 frame 的当前项后保留 150 项。页面脚本也能通过桥接提供 frameID，因此不能依赖它们天然很少。增加硬容量规则，并同步清理 frame 索引；具体容量无需扩大。 |
| F6 | P2 | README 的测试命令在多套运行时环境下失效。 | 实际 `make test SIMULATOR='iPhone 16 Pro'` 返回错误 70；Xcode 将未给 OS 的 destination 解析为 OS:latest，而 iPhone 16 Pro 仅存在于 iOS 18.6。`Makefile:34` 没有使用已经定义的 `SIMULATOR_ID`。建议支持 UUID 优先，或显式 OS，并同步双语 README。改用确切 UUID 后现有测试通过。 |

复现材料位于 [audit-2026-10-18/](audit-2026-10-18/)，其中 Node 夹具使用模拟 DOM 事件，Swift 夹具直接编译仓库的 CandidateStore。它们确认特定逻辑问题，不证明真实站点已经触发，也不属于新增的 XCTest 覆盖。

## 代码风险与体验优化

以下事项应排进后续工作，但本次没有按“真实设备已复现缺陷”计算。

1. **投屏失败后的手机播放恢复。** `ContentView.swift:104` 在 `load()` 刚返回 true 时立即暂停所有本地媒体、关闭候选页并切到遥控页；此时只表示发送了异步请求，并不表示电视已播放。建议用接收端播放状态确认交接，或在失败时提供“返回网页继续播放”。保留避免手机与电视同时出声的目标，验收加载成功和失败两条路径。
2. **当前正片的排序。** `CandidateStore.sorted` 先排所有 master，再排 current。因此一个旧广告 master 会排在正在播放的 MP4 正片前。该顺序是现有测试明确固定的行为，不是测试遗漏；应调整产品规则为当前相关内容优先，同一内容内再优先 master，同时修改对应测试。
3. **连接中的取消与恢复。** 遥控页在 connecting 时禁用主要入口，没有明显的取消操作；suspended 的“断开并重试”实际只打开停止确认并断开，不会自动重试。建议统一操作名称，补齐取消、失败回到可重试状态、切换电视和等待恢复期间选片的状态测试。
4. **失败诊断。** 当前大部分连接、加载、播放器失败都给出通用提示。先保留 SDK 错误码、失败阶段和时间的脱敏诊断，避免记录完整签名 URL、Cookie 或请求头；再按可观察原因提供重试或重新检测入口。当前代码无法从通用错误可靠推断一定是 CORS、DRM 或 token 失效。
5. **可访问性与窄屏。** 多数图标按钮已有无障碍标签，主要浏览操作使用 44pt 热区；但地址清空按钮没有显式最小热区，候选徽章行在特大字体下没有换行策略。需实测 VoiceOver、特大字体、横屏、长设备名与 iPad，不能仅凭源代码宣布通过。本轮未获得可用的 Simulator CUA 界面绑定，因此未进行交互式视觉验收。

## 配置、隐私与分发

- SwiftUI + WKWebView，最低 iOS 16；Google Cast 固定 4.8.6，revision 与锁文件一致。依赖仍使用第三方 SPM 包装；实际下载的 framework、checksum 和包定义存在本地缓存。Google [2026-07-27 发布说明](https://developers.google.com/cast/docs/release-notes)列出 4.8.6，最低 iOS 16，与工程一致；没有发现需要为版本号而升级的证据。
- Info.plist 的本地网络权限、两个 Bonjour 服务和网页 ATS 配置存在。Release 关闭详细 Cast 日志，离线验证与调试入口受 DEBUG 限制；脚本桥只写候选，不会直接连接或控制电视。
- **公开分发前的缺口：App 自身没有 PrivacyInfo.xcprivacy。** Release 包里只找到 GoogleCast.framework 自带清单，而 App 的设置、上次页面/标签等直接使用 UserDefaults。Apple 要求 App 自己的 required reason API 用法在 App 所属 bundle 声明，不能靠依赖清单代替。需按真实用途补齐后检查 Archive 的隐私报告；这是未来 App Store Connect 分发准备项，未进行上传验证。[Apple 官方要求](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api)。
- 自用签名、无公开二进制和无项目许可证均已在 README 说明，不当作本轮必须新建的功能。旧安装记录的描述文件到期日为 2026-10-14；本次没有查询当前手机，因此不能判断手机是否已重新签名。
- `PLAN.md` 末尾仍保留早期“未签名、未安装、电视未验证”的实施快照；README 与后续证据已记录安装和用户成功播放反馈。保留历史时应显式标注为早期快照，并链接最新审查，避免将其当作当前状态。
