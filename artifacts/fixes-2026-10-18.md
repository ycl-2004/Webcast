## 修复内容

| 要求 | 处理 | 验证方式 |
| --- | --- | --- |
| F1 断开行为与文案 | 设备页和遥控页统一为“停止并断开”，均需确认；移除内部 `stopPlayback` 布尔参数，明确请求停止。清理旧翻译，更新双语 README。 | 调用点与资源检查；SwiftUI 编译；真实接收端行为仍需验收。 |
| F2 系统播放/暂停 | CastManager 提供明确的 play/pause；系统三种命令分别映射到 play、pause、toggle。 | 可注入目标的命令路由测试，验证重复 play/pause 保持期望状态，只有 toggle 反转状态。真实系统事件到接收端的完整链路未验收。 |
| F3 A → B → A 激活丢失 | 激活切换独立于 URL 元数据去重；重复的同视频事件仍去重。MSE 使用 master 作为首选当前项，缓存恢复时最后重放当前项。 | 原 Node 夹具已得到 A、B、A；新增真实 WKWebView 激活切换、重复事件和缓存恢复测试。 |
| F4 跨框架标记错误 | 当前状态从所有已跟踪 frame 的 URL 引用推导；一个 frame 换片不会清除其他 frame 的引用。 | 新增共享 URL 的两个 frame 依次换片测试；原 Swift 夹具现标记正确。 |
| F5 容量限制失效 | 候选和活动 frame 均限制为 100。优先淘汰非当前候选；必要时淘汰最旧当前项并清理引用。 | 新增全部当前项、保留当前项、同 URL 大量 frame 及 reset 的边界测试；原 150 项夹具现保留 100 项。 |
| F6 多运行时测试入口 | `make test` 支持 UUID 优先的 `SIMULATOR_ID`，以及名称搭配 `SIMULATOR_OS`；双语 README 提供两种用法。 | 实际通过 Makefile 运行测试；dry-run 验证 UUID 优先级与显式 OS 的 destination。 |

F1 的取舍：本轮修复的是错误的行为承诺，当前只提供明确的停止操作。没有添加“电视继续播”的替代会话策略。Google Cast SDK 明确说明单发送端下 stopCasting=false 仍会停止接收端，因此不能靠 false 参数承诺保留播放。[Google 官方 API](https://developers.google.com/cast/docs/reference/ios/interface_g_c_k_session_manager)。

F2 保留一个小的命令目标协议，使同一生产路由可以脱离真实 Cast 会话验证重复命令的行为；SDK 传输和错误追踪仍留在 CastManager。[Apple 系统播放命令定义](https://developer.apple.com/documentation/mediaplayer/mpremotecommandcenter)。

F5 的取舍：极端页面有超过 100 个活动 frame 时，仅跟踪最近 100 个；避免页面报告使内存无界增长。候选排序维持原规则，优先 master 的产品优化不属于本轮 6 项缺陷。
