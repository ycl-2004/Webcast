## Implementation decisions and limits

- Keep native SwiftUI/WKWebView and receiver-direct playback. No proxy, background audio or unrelated feature expansion.
- Media revisions are conservative across frames: an unrelated frame change may leave phone playback running after the TV loads. This protects new local playback from late confirmation.
- Diagnostics are deliberately ephemeral. Capture their visible fields before restarting the app when investigating a failure.
- [Upstream wrapper rejection evidence](fixes-2026-10-24/official-wrapper-rejected.txt). The official package initially failed to resolve into a modified legacy cache; a separate cache preserved that checkout. The first compile then exposed direct `GCK*` symbol linkage through the shared dynamic wrapper. Explicit framework linkage corrected compilation, but deeper runtime-class inspection rejected this wrapper. The final local binary-only manifest removes both that linkage workaround and the duplicate networking dependency. An intermediate test run had four hardcoded Chinese expectations; assertions now follow localization and passed on the subsequent run.
- The first iOS 26.5 full run had two initial-page fixture failures (76/78 passed), including WebKit unresponsiveness and cascading JavaScript errors. [Failed-run summary](fixes-2026-10-24/tests-ios26-initial-failures.json). The two cold-start navigation fixtures now attach to visible windows; prerequisite timeouts throw instead of producing cascades. Both [focused tests passed](fixes-2026-10-24/tests-ios26-focused.json), followed by the final 78/78 full suite.
- An intermediate iOS 18.6 run with the corrected package reached 77/78; a detached route/timer fixture timed out while WebKit processes launched slowly. [Retained log excerpts](fixes-2026-10-24/ios18-timeout.txt). Its result bundle was left incomplete by interruption, so it is not used as a successful run. The fixture now stays foregrounded with teardown cleanup; its [focused test](fixes-2026-10-24/tests-ios18-focused.json) and final 78/78 suite passed without increasing timeouts or weakening assertions.
- A later iOS 26.5 full run exposed a Swift concurrency/XCTest abort in the SPA fixture after globally attaching test WebViews to windows. Visibility setup was narrowed to the two cold-start cases, avoiding duplicate windows in the SPA fixture. A synthetic source-switch test also raced WebKit’s real asynchronous source-reset event; it now waits for reset and explicitly supplies the synthetic current source. Both affected tests passed in a focused run with the corrected binary-only package. These are test-harness changes; product behavior assertions remain.
- Local tools use Xcode 27.1. The pinned remote Xcode 26.3 workflow has not run here. iOS 16 and physical iPad remain untested.
- No physical installation, receiver discovery/control, signing, commit, push or publication was performed. Real playback, target-site episode compatibility, 1–2-hour continuity, lock/unlock and Wi-Fi recovery remain [hardware acceptance items](../docs/ACCEPTANCE.md).
