# Isolated detection bridge and explicit receiver QA

Date: 2026-10-26. Status: implemented in source, build 0.1.2 (4).

The review demonstrated that any website could call the page-world native message handler, invent a restored generation and claim arbitrary current media. Several metadata fields also retained arbitrarily large strings. The app must continue observing site fetch/XHR and media sources, while treating those observations as untrusted data.

The same detection resource now runs in two worlds. The page collector observes fetch/XHR and media-source setters, forwarding only network/source metadata through window messages. The isolated `WKContentWorld.defaultClient` observer handles DOM playback, frame lifecycle and the native bridge. Only messages from its own frame's WindowProxy can supply observations. Page messages cannot supply current flags, lifecycle commands, generation or frame identity. It re-reads the actual location for SPA transitions and rejects observations posted for a different route. Source hooks in the page world remain necessary for detached preloads that a DOM observer cannot see.

Native input validation whitelists fields and types, bounds UTF-8 strings and total retained data, rejects nested/unknown fields and keeps signed URL queries intact. Separate token budgets reserve lifecycle processing during media floods. Per-frame budgets and pending latest observations have bounded storage; pending observations are cancelled on route/inactive/removal and checked against accepted generations before draining. UI publication is coalesced for 50 ms. Selection-time handoff reads the immediate store, never the delayed display list, so a stale row cannot arm local pause for replacement media.

A restored generation must have been issued by native code. A native post-commit query of the isolated world's generation and replay hook handles back/forward cache event ordering; the document identity guards against callbacks from a subsequent navigation. Frame IDs are bookkeeping, not authentication. Websites still control their DOM, media URLs and network messages; a current/MSE badge is an observation/inference, not proof of decoded video. No bridge message can connect or control a receiver. User action and native load validation remain required. This does not eliminate the IPC cost incurred before the native handler receives a message, nor replace WebKit updates.

Connection/recovery waits have a 30-second foreground deadline. Timeout publishes an error and cancels queued media; it does not invent a disconnection or replace SDK recovery. A late SDK connection may still complete, but cancelled queued media must not load. Backgrounding cancels the wait task; returning to a suspended session starts a new foreground deadline. Stop/disconnect remains the explicit recovery exit.

`WebcastReceiverAcceptance` is a separate manual scheme. Normal `Webcast` tests/CI remain offline. Its test skips without an explicitly selected receiver ID. `scripts/run_receiver_acceptance.py` requires `--allow-control`, installs a temporary receiver ID into the generated test-run environment and removes that authorized specification afterward. It uses the same `CastManager`/`MediaLoader` as the app, at low test volume, then stops media, restores volume/mute and disconnects. It does not enable provisioning updates. Running physical tests may require a separately authorized signing setup.

Tradeoff: two isolated observers and bounded/coalesced delivery add complexity, but remove the direct page-to-native privileged channel without discarding fetch/XHR detection. HTTP/private media policy, incognito browsing, subtitles, queues and new receiver protocols are deferred. No proxy, backend or background keep-alive is added.
