# Webcast 0.1.2 (4)

First GitHub prerelease, packaged on 2026-10-28. Browse web videos on iPhone, select a detected stream, and send it directly to a Chromecast or Google Cast receiver on the same Wi-Fi.

## Downloads and installation

| Asset | Purpose |
| --- | --- |
| `Webcast-0.1.2-iOS-unsigned.ipa` | arm64 iOS 16+ Release. **Unsigned: requires your own Apple signing before installation.** No personal provisioning profile is included. Building with your own team in Xcode is the documented phone-install path. |
| `Webcast-0.1.2-Simulator.zip` | Release app for an iOS Simulator on a Mac with Xcode. Contains arm64 and x86_64 slices; ad-hoc signed without an Apple account identity. Installation and launch verified on Apple Silicon with iOS 18.6. |
| `Webcast-0.1.2-ThirdPartyNotices.zip` | Open-source notices supplied with the pinned Google Cast 4.8.6 SDK archive. Dependencies retain their own licenses. |
| `release-manifest.json` | Build version, configuration, architectures, toolchain, build-source commit, product-file hashes and bundle-verification results. |
| `SHA256SUMS` | SHA-256 digests for the four files above. |

[Download assets](https://github.com/ycl-2004/Webcast/releases/tag/v0.1.2). There is no App Store or TestFlight release. The separately signed development build tested on the author's iPhone is not distributed; its provisioning does not cover other phones.

To try the simulator app, unzip the simulator ZIP, open a simulator in Xcode, and run these commands from the directory containing `Webcast.app`:

```sh
xcrun simctl list devices booted
xcrun simctl install '<BOOTED_SIMULATOR_UUID>' Webcast.app
xcrun simctl launch '<BOOTED_SIMULATOR_UUID>' dev.yc.Webcast
```

Use the UUID from the first command. For a phone, follow [Build from source](../../README.md#build-from-source) with your own Apple team. Local Network permission and a same-Wi-Fi Cast receiver are required for casting.

To verify downloaded files, place the five assets together, then run:

```sh
shasum -a 256 -c SHA256SUMS
```

## Included in this release

- Native SwiftUI browser, configurable home page, URL/search entry and local website-data clearing.
- HLS/MP4 detection, current-video prioritization, source/duration details and inferred-MSE labeling.
- Chromecast discovery, remembered receiver, playback/seek/volume/mute/stop controls and in-memory failure diagnostics.
- Isolated native WebKit detection bridge, typed input and message budgets, route/frame-aware media bookkeeping and selection-context checks.
- Foreground connection/recovery deadline with cancellation of pending media after 30 seconds.
- English, Simplified Chinese and Traditional Chinese UI resources and Local Network permission text.

## Known limits

DRM, browser cookies, required request headers, expiring URLs and receiver codec support can prevent playback. There is no relay, screen mirroring, AirPlay, DLNA, background-audio keep-alive, queue or subtitle support. Full browser-to-TV UI acceptance, human picture/sound confirmation, lock-screen/Wi-Fi recovery, long playback, iOS 16 and physical iPad acceptance remain pending.

## Reproduce the packages

```sh
make check-release
make release
python3 scripts/package_release.py --output artifacts/Release/v0.1.2
```

Requires macOS, Xcode, XcodeGen and Python 3. The output directory must not already contain these release filenames. The script validates both input bundles, packages the unsigned device app as `Payload/Webcast.app`, ad-hoc signs a staged simulator copy, includes SDK notices and writes the manifest/checksums. Local signing configuration and personal device identifiers are excluded.
